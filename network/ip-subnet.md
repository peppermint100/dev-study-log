## ip란?

ip는 인터넷 상에 연결된 기기들의 집 주소를 뜻한다. 보통 점으로 구분된 4개의 숫자로 이루어져있다(예: 192.168.0.1)

- 구조: 각 숫자를 옥텟(Octet)이라고 부르며 0부터 255까지의 숫자가 들어갈 수 있다.
    - 주소 한 칸(옥텟)이 8비트로 이루어져 있다 (2^8 = 256)
- 사람은 10진수로 인식하지만 컴퓨터는 이를 32개의 비트(2^32)로 인식한다.(1옥텟 * 4)
- 32비트 체계로는 약 43억개의 주소만 만들 수 있어서 주소 부족 문제를 해결하기위해 ipv6가 등장했다.

일반적으로 ip라고 하면 ipv4를 의미하며 ipv6는 ipv4와 다르게 128비트(16비트 * 8)개로 이루어져 있으며 점이 아닌 콜론(:)으로 나눈다. (예: 2001:0db8:85a3) 다만 ipv4 전용장비는 ipv6를 전혀 이해할 수 없고, NAT라는 주소변환 기술덕분에 공인 ip하나로도 수백 대의 기기가 인터넷을 쓸 수 있게 되어 사람들에게 익숙한 ipv4가 더 많이 사용된다.

## 네트워크 ID, 호스트 ID, 서브넷 마스크

ip주소는 두 부분으로 나누어져 있다. 하나는 네트워크 ID, 하나는 호스트 ID이다. 

- 네트워크 ID: 어떤 네트워크에 속하는지
- 호스트 ID: 네트워크에서 어떤 기기에 속하는지

네트워크 ID와 호스트 ID의 경계는 설계자의 의도에 따라 달라진다. 예를 들어 앞의 3옥텟을 네트워크 ID로 하고 나머지 1옥텟을 호스트 ID로 할 수도 있고, 앞의 2옥텟을 네트워크로 하고 뒤의 2옥텟의 호스트로 할 수도 있다.

이 경계선을 알려주는 것이 서브넷 마스크이다.

서브넷 마스크의 규칙은 단순한데, **1인 부분은 네트워크 ID, 0인 부분은 호스트 ID**이다. 

즉 255.255.255.0이면 앞의 3옥텟은 네트워크 ID, 뒤의 1옥텟은 호스트 ID에 해당한다(앞의 255를 2진수라고 가정한다. 그러면 전부 1이다.)

```sql
# 255.255.255.0의 서브넷 마스크를 가진 ip 예시
1번 컴퓨터: 192.168.0.1
2번 컴퓨터: 192.168.0.2
3번 컴퓨터: 192.168.0.100
```

서브넷 마스크는 255.255.0.0 이런 방식 말고 다른 방식으로도 표현하는데, 10.0.0.0/16이라고 표기하기도 한다. 이는 앞의 16개의 비트가 1이라는 뜻으로 즉, 255.255.0.0의 서브넷 마스크를 가지는 셈이다.

이렇게 255.255.255.0 대신 10.0.0.0/16 이라고 표기하는 방법을 CIDR 표기법이라고 한다.

10.0.0.0/16에서는 총 몇 대의 기기(호스트)에게 IP를 줄 수 있을까? 정답은 앞의 16비트가 네트워크이므로 뒤의 16비트가 호스트비트이므로 총 2^16개의 기기를 할당할 수 있게 되는 것이다.

## 예약된 특수 IP

cidr가 `/24` 인 대역에서 호스트 개수가 256개이지만, 실제로 기기에 할당할 수 있는 개수는 조금 더 적다.

- Network Address: 그 구역의 대표이름으로 호스트 비트가 모두 0인 주소이다.(예: 10.0.0.0)
- Broadcast Address: 그 구역의 모든 기기에 동시에 전달할 때 쓰는 주소이다. 호스트비트가 모두 1인 주소이다.(예: 10.0.0.255)
- 클라우드 예약 주소: AWS 같은 곳에서 관리목적으로 몇 개의 주소를 더 예약해둔다.

네트워크 주소와 브로드캐스트 주소는 우리가 직접 사용하진 않지만 네트워크 장비들을 전부 찾거나 한꺼번에 데이터를 보낼 때 사용된다. (예: 10.0.0.0/24 → 호스트 ID가 0으로 특정 서브넷 대역을 대표한다.)

## 사설 IP 대역

RFC 1918 대역이라고 하는 전 세계적으로 해당 숫자는 내부 네트워크용으로만 쓰자고 약속된 대역이 있다.

- Class A: 10.0.0.0 ~ 10.255.255.255 - 대규모 기업, 거대한 VPC
- Class B: 172.16.0.0 ~ 172.31.255.255 - 중규모 네트워크
- Class C: 192.168.0.0 ~ 192.168.255.255 - 소규모, 가정용 공유기
